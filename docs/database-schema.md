# Database Schema Overview

The backend uses PostgreSQL with Prisma as the ORM. The schema mirrors the three datasets plus authentication metadata. All tables live in the default `public` schema.

## Entity Diagram

```
User 1 ──── 1 UserProfile
User 1 ──── * MonthlyExpense
User 1 ──── * FinancialHealth
```

## Tables

### `users`
| Field | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated by Prisma. |
| `email` | `text` | Unique, lowercase. |
| `password` | `text` | Bcrypt hash. |
| `first_name` / `last_name` | `text` | Basic identity info. |
| `phone` | `text` | Unique, must include country code. |
| `created_at` | `timestamp` | Defaults to `now()`. |
| `updated_at` | `timestamp` | Auto-managed via Prisma. |
| `last_login` | `timestamp` | Updated on each successful login. |

### `user_profiles`
Represents Dataset 1 (household + baseline financial info). Enforces a one-to-one relationship with `users` via `user_id` (unique).

Key columns (snake_case in DB, camelCase in Prisma client):
- Demographics: `household_size`, `num_adults`, `num_children`, `location_type`, `life_stage`.
- Work & income: `employment_status`, `monthly_household_income`, `income_stability`.
- Debt & housing: `credit_score`, `total_debt`, `monthly_debt_payments`, `rent_or_mortgage`.
- Goals & insurance: `savings_goal_monthly`, `has_health_insurance`, `financial_goal_type`, `emergency_fund_months`.
- Derived metrics: `savings_rate_percentage`, `debt_to_income_ratio`, `housing_cost_ratio`, `monthly_savings_actual`, `financial_health_score`, `optimization_priority`.

### `monthly_expenses`
Captures Dataset 2 with per-category spending plus derived totals. Composite unique constraint on (`user_id`, `month_year`) prevents duplicate records per month.

Columns:
- `month_year` (`date` stored as first day of month).
- Category totals: `housing_utilities`, `groceries`, `restaurants_cafes`, `transportation_fuel`, `public_transport`, `healthcare_pharmacy`, `education_tuition`, `childcare`, `clothing_personal_care`, `entertainment_hobbies`, `subscriptions`, `other_shopping`, `gifts_charity`, `miscellaneous`.
- Derived metrics: `total_expenses`, `total_essential_spending`, `total_discretionary_spending`, `essential_spending_ratio`, `discretionary_spending_ratio`, `savings_this_month`, `spending_vs_last_month_percentage`, `highest_spending_category`, `meets_50_30_20_rule`.

### `financial_health`
Optional Dataset 3 table for storing historical assessments per month. Unique per (`user_id`, `month_year`).

Fields include:
- Metrics: `financial_stress_level`, `financial_health_score`, `optimization_priority`.
- Negative flags: `needs_emergency_fund`, `overspending_restaurants`, `overspending_entertainment`, `overspending_subscriptions`, `high_debt_burden`, `insufficient_savings`, `housing_cost_too_high`, `lifestyle_inflation_detected`, `irregular_savings_pattern`.
- Positive indicators: `has_adequate_emergency_fund`, `healthy_savings_rate`, `controlled_discretionary_spending`, `low_debt_burden`.
- Summary fields: `overall_financial_health`, `needs_optimization`, `optimization_urgency`, `top_3_problem_areas` (stored as JSON text).

## Relationships & Cascades
- `user_profiles.user_id` → `users.id` (`onDelete: Cascade`).
- `monthly_expenses.user_id` → `users.id` (`onDelete: Cascade`).
- `financial_health.user_id` → `users.id` (`onDelete: Cascade`).

Deleting a user automatically removes all related snapshots. Monthly expense changes trigger `updateProfileHealthScore` to keep profile health metadata in sync.

## Prisma Notes
- Run `npx prisma migrate dev` (development) or `npx prisma migrate deploy` (production) after altering `schema.prisma`.
- Generated client version is pinned via `package.json`. Update with `npm run prisma:generate` whenever the schema changes.
- `DATABASE_URL` must point to a PostgreSQL database (local `postgres://...` or managed service).
